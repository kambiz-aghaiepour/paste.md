# Phase 2 — UI Design Contract

> Visual and interaction contract for the Markdown rendering and editor phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (plain Tailwind utility classes) |
| Icon library | none (no icons needed in this phase) |
| Font | System font stack (Tailwind `font-sans` default) + `font-mono` for editor textarea and code blocks |

Rationale: The project uses Tailwind CSS v4 with CSS-first config. No shadcn is initialized and none is needed -- this phase has only 3 interactive elements (textarea, submit button, mobile toggle). Adding a component library would add friction for zero benefit.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | Inline icon gaps (not used in this phase) |
| sm | 8px (`gap-2`, `p-2`) | Toggle button internal padding, compact gaps |
| md | 16px (`gap-4`, `p-4`) | Default element spacing, textarea padding, prose container padding |
| lg | 24px (`gap-6`, `p-6`) | Code block padding inside prose |
| xl | 32px (`gap-8`, `p-8`) | Page-level padding (`main` container), section gaps |

Exceptions: none

## Typography

| Role | Size | Weight | Line Height | Where Used |
|------|------|--------|-------------|------------|
| Body / Prose | 16px (Tailwind default) | 400 (normal) | 1.5 | Rendered Markdown body text via `prose` class |
| Editor text | 14px (`text-sm`) | 400 (normal) | 1.5 | Textarea content, monospaced |
| Page heading | 30px (`text-3xl`) | 700 (bold) | 1.2 | "paste.md" site title (inherited from Phase 1) |
| Meta / Label | 14px (`text-sm`) | 500 (medium) | 1.4 | Timestamps, "Draft restored" indicator, toggle labels |

Notes:
- Prose headings (h1-h6 inside rendered Markdown) are controlled by `@tailwindcss/typography` defaults. Do not override.
- Editor textarea uses `font-mono` (system monospace stack). Prose output uses `font-sans` (system sans stack).
- Tailwind typography plugin `prose` class uses 16px body with 1.75 line-height by default. Accept the plugin defaults for rendered content -- they are designed for long-form reading.

|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Page background, editor background, preview background |

## Component Inventory

### View 1: Editor Page (Home `/`)

```
+------------------------------------------------------+
|  paste.md                                    [h1]     |
+------------------------------------------------------+
|                                                       |
|  +-------------------------+  +---------------------+ |
|  |  Editor (textarea)      |  |  Preview (prose)    | |
|  |                         |  |                     | |
|  |  font-mono, text-sm     |  |  prose class        | |
|  |  min-h-[calc(100vh-     |  |  overflow-y-auto    | |
|  |    280px)]               |  |  same height as     | |
|  |                         |  |  editor              | |
|  |                         |  |                     | |
|  +-------------------------+  +---------------------+ |
|                                                       |
|  [error message if any]                               |
|  [============ Create Paste ============]             |
+------------------------------------------------------+
```

**Desktop (>= 768px / `md` breakpoint):**
- 50/50 horizontal split (D-10)
- Both panes visible simultaneously
- Split implemented with `grid grid-cols-2` and `gap-4` (16px gutter)
- Both panes have matching height: `min-h-[calc(100vh-280px)]`
- Editor pane: bordered textarea with `rounded-lg border border-gray-300`
- Preview pane: bordered container with `rounded-lg border border-gray-200` and `p-4` inner padding
- Preview pane header: "Preview" label in `text-sm font-medium text-gray-500` above the prose area
- Error message spans full width below the split
- Submit button spans full width below error

**Mobile (< 768px):**
- Stacked layout with toggle (D-11)
- Segmented control at top: two buttons "Edit" | "Preview"
- Toggle container: `flex rounded-lg border border-gray-200 overflow-hidden` above the content area
- Active tab: `bg-blue-600 text-white`
- Inactive tab: `bg-white text-gray-600`
- Each tab button: `flex-1 py-2 text-sm font-medium text-center`
- Only one pane visible at a time
- Content area: full width, same border treatment as desktop panes

### View 2: Paste View Page (`/[slug]`)

```
+------------------------------------------------------+
|                                                       |
|  [Rendered Markdown content]                          |
|                                                       |
|  - prose class from @tailwindcss/typography            |
|  - Shiki syntax highlighting in code blocks           |
|  - GFM: tables, task lists, strikethrough             |
|                                                       |
+------------------------------------------------------+
|  Created: 2026-05-14T...                              |
+------------------------------------------------------+
```

- Layout container: `max-w-3xl mx-auto p-8` (inherited from Phase 1)
- Rendered content: wrapped in `<article class="prose prose-gray max-w-none">`
- `max-w-none` overrides prose's built-in max-width since the outer container already constrains width
- Timestamp: `text-sm text-gray-500 mt-4` (inherited from Phase 1)
- No back-to-home link on paste view (keep it clean -- user uses browser back or edits URL)

### Draft Restored Indicator

```
+------------------------------------------------------+
|  [i] Draft restored                           [x]    |
+------------------------------------------------------+
```

- Position: above the editor/split area, below the h1 title
- Full width of content area
- Background: `bg-blue-50`, text: `text-blue-700`, border: `border border-blue-200`
- Rounded: `rounded-lg`
- Padding: `px-4 py-2`
- Layout: `flex items-center justify-between`
- Dismiss button: plain `x` text in `text-blue-400 hover:text-blue-600`, no icon library needed
- Auto-dismiss: fades out after 3 seconds via CSS transition (`opacity-0 transition-opacity duration-300`)
- If no draft exists in localStorage, this element is not rendered

## Interaction Contracts

### Live Preview (D-08, D-09)

| Property | Value |
|----------|-------|
| Trigger | User types in textarea |
| Debounce | 300ms after last keystroke |
| Rendering | Client-side react-markdown with remark-gfm and rehype-sanitize |
| Syntax highlighting | None in preview (D-06) -- plain `<pre><code>` styling |
| Empty preview | Show nothing (empty div) when textarea is empty |
| Scroll | Preview pane scrolls independently (`overflow-y-auto`) |

### localStorage Draft Persistence (D-13, D-14, D-15)

| Property | Value |
|----------|-------|
| Save trigger | Keystroke in textarea |
| Save debounce | 1000ms after last keystroke |
| Storage key | `paste-md-draft` |
| Storage value | Plain string (textarea content) |
| Restore trigger | Component mount (`useEffect`) |
| Restore behavior | Set textarea value, show "Draft restored" indicator |
| Clear trigger | Successful paste creation (after redirect) |
| Error handling | Catch `QuotaExceededError` silently -- do not block paste creation |

### Mobile Toggle (D-11)

| Property | Value |
|----------|-------|
| Default view | Edit (textarea visible) |
| Toggle behavior | Swap between Edit and Preview views |
| State preservation | Toggling to Preview does not clear textarea; toggling back restores the same content |
| Animation | None (instant swap for simplicity) |

### Form Submission

| Property | Value |
|----------|-------|
| Method | POST to `/api/paste` (inherited from Phase 1) |
| On success | Clear localStorage draft, redirect to paste URL |
| On error | Display inline error below editor |
| Button state | Disabled during submission with "Creating..." text |

## Shiki Configuration

| Property | Value |
|----------|-------|
| Theme | `github-light` |
| Integration | `@shikijs/rehype` plugin in the rehype pipeline |
| Rendering context | Server Component only (paste view page) |
| Languages | All bundled languages (Shiki lazy-loads grammars) |
| Code block styling | Shiki generates inline styles; wrap in `overflow-x-auto` for horizontal scroll on long lines |

Rationale for `github-light`: Matches the project's content-focused aesthetic. Users expect GitHub-quality Markdown rendering (stated in REQUIREMENTS.md). Dark theme variant (`github-dark`) will be added in Phase 5 with dark mode support.

## Prose Styling Overrides

The `@tailwindcss/typography` `prose` class provides sensible defaults. Override only where necessary:

| Element | Override | Reason |
|---------|----------|--------|
| `a` (links) | `prose-a:text-blue-600 prose-a:no-underline hover:prose-a:underline` | Match accent color, cleaner default appearance |
| `code` (inline) | `prose-code:before:content-none prose-code:after:content-none` | Remove backtick characters that typography plugin adds by default |
| `pre` (code blocks) | `prose-pre:bg-transparent prose-pre:p-0` | Defer to Shiki's styling for server-rendered code blocks |
| `img` | `prose-img:rounded-lg` | Consistent border radius with other elements |
| `table` | `prose-table:overflow-x-auto` via wrapper | Allow horizontal scroll on wide tables |

Apply these overrides via Tailwind modifier classes on the `prose` wrapper element. Do not create custom CSS.

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| Textarea label | `<label>` element or `aria-label="Markdown editor"` on textarea |
| Preview region | `role="region" aria-label="Markdown preview"` on preview container |
| Live preview updates | `aria-live="polite"` on preview container so screen readers announce content changes (debounced) |
| Mobile toggle | Toggle buttons use `aria-pressed` to indicate active state |
| Draft indicator | `role="status"` for the "Draft restored" notification |
| Error messages | `role="alert"` on error text (inherited from Phase 1) |
| Focus management | Tab order: textarea -> toggle (mobile) -> submit button. No focus traps. |
| Keyboard | Standard form keyboard behavior. No custom keyboard shortcuts in this phase. |
| Color contrast | All text meets WCAG 2.1 AA (4.5:1 minimum). blue-600 on white = 4.75:1. gray-500 on white = 4.64:1. |
