## Phase Goal

**As a** paste author, **I want to** preview my Markdown in real-time while editing and have my draft saved automatically, **so that** I can verify formatting before sharing and never lose work to accidental page closure.

<objective>
Create the custom hooks (useDebounce, useLocalStorageDraft), the client-side MarkdownPreview component, the DraftIndicator component, and extend PasteForm with split-pane layout, live preview, mobile toggle, and localStorage draft persistence.

Purpose: After this plan, users can type Markdown in a split-pane editor and see a live preview update in real-time. On mobile, they toggle between edit and preview. Drafts are automatically saved to localStorage and restored on page load. This completes the editor experience.

Output: Fully functional editor with live preview, split-pane layout, mobile toggle, and draft persistence.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> client-side preview | User-typed Markdown rendered in the same browser session via react-markdown |
| localStorage -> editor state | Draft content restored from localStorage into textarea on page load |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | MarkdownPreview (XSS via client-side rendering) | mitigate | react-markdown ignores raw HTML by default; rehype-sanitize strips non-schema elements; same defense-in-depth as server path per D-04 |
| T-02-07 | Tampering | useLocalStorageDraft (malicious content injection via localStorage) | accept | localStorage is same-origin only; an attacker with localStorage write access already has full page control; restoring draft into a textarea (text-only) carries no XSS risk; content is then sanitized when rendered in preview via rehype-sanitize |
| T-02-08 | Information Disclosure | useLocalStorageDraft (draft content persisted in browser) | accept | Users expect draft persistence (D-13); content is cleared after successful paste creation (D-15); localStorage is same-origin and user-controlled |
| T-02-09 | Denial of Service | MarkdownPreview (rendering large Markdown on every keystroke) | mitigate | 300ms debounce prevents rendering on every keystroke per D-08; paste content is bounded to 512KB max by Phase 1 validation |
</threat_model>
