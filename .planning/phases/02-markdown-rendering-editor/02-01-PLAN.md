<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User content -> Markdown renderer | Untrusted paste content (user-submitted Markdown) crosses into the rendering pipeline |
| Markdown AST -> HTML output | Transformed AST produces HTML that is served to viewers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | MarkdownRenderer (XSS via script tags, event handlers) | mitigate | react-markdown ignores raw HTML by default; rehype-sanitize strips anything not in default schema; plugin runs BEFORE Shiki so untrusted input is sanitized first |
| T-02-02 | Tampering | MarkdownRenderer (XSS via javascript: URLs in links) | mitigate | react-markdown's built-in defaultUrlTransform strips javascript: and vbscript: protocols automatically |
| T-02-03 | Tampering | MarkdownRenderer (DOM clobbering via id/name attributes) | mitigate | rehype-sanitize prefixes id and name with user-content- per GitHub's approach |
| T-02-04 | Tampering | MarkdownRenderer (CSS injection via style attributes) | mitigate | rehype-sanitize runs before Shiki; user input never produces style attributes; only Shiki (trusted server-side code) generates inline styles |
| T-02-05 | Denial of Service | MarkdownRenderer (pathological Markdown input) | accept | micromark parser has O(n) complexity for well-formed input; deeply nested structures may slow rendering but do not crash; paste size limit (512KB from Phase 1) bounds input size |
</threat_model>
