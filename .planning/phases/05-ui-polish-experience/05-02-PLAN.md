    1. **copy-button.tsx** -- Create Client Component ("use client"). Import useState from react. Accept props: textContent of type string (the code text to copy), and optional className. Use navigator.clipboard.writeText(textContent) on click. Manage copied state via useState(false). On successful copy, set copied to true and setTimeout to reset after 2000ms per D-08. Clean up timeout on unmount via useEffect return. Render a button with:
       - aria-label dynamically set to "Copied" when copied, "Copy code" when idle
       - Two inline SVGs: clipboard icon (idle) and checkmark icon (copied) per UI-SPEC copywriting contract
       - Classes: p-2 rounded-md for sizing, bg-gray-100/80 dark:bg-gray-700/80 hover:bg-gray-200 dark:hover:bg-gray-600 for background, text-gray-500 dark:text-gray-400 for icon color

       - focus-visible:ring-2 focus-visible:ring-blue-500 for keyboard accessibility
       - min-h-[44px] min-w-[44px] per D-12 touch targets
       - Wrap the click handler in try/catch -- silent fail on clipboard API error per UI-SPEC

    2. **copyable-pre.tsx** -- Create Client Component ("use client"). Import useRef from react and CopyButton from @/app/components/copy-button. Accept props: children (React.ReactNode) and rest props spread onto the pre element. Use a ref on the pre element. Render a div with className "relative group" wrapping the original pre (with ref and all spread props) plus a CopyButton positioned absolute top-2 right-2. The CopyButton receives textContent={preRef.current?.textContent ?? ""}. For the hover-reveal behavior per UI-SPEC: the CopyButton wrapper has opacity-0 group-hover:opacity-100, but on touch devices (no hover capability), use a media query approach -- add a CSS class or Tailwind arbitrary variant so the button is always visible when @media (hover: none). The simplest approach: combine opacity-0 group-hover:opacity-100 with a [@media(hover:none)]:opacity-100 arbitrary variant on the button container.

    3. **paste-view.tsx** -- Per D-09, the PasteView Client Component must add copy buttons to code blocks in the server-rendered content. Since renderedContent is pre-rendered RSC output (React.ReactNode), the components prop approach on MarkdownAsync cannot be used from here. Instead, use a client-side DOM approach: add a useEffect that queries all pre elements within the rendered content container, and for each pre, creates a wrapper div with position:relative and a CopyButton overlay. Use useRef on the rendered content container div. Import CopyButton from @/app/components/copy-button and createPortal from react-dom. For each pre element found via querySelectorAll("pre"), create a portal-rendered CopyButton. Alternative simpler approach: wrap the renderedContent div with a ref, and in useEffect create a MutationObserver or simply query pre elements and inject copy buttons using DOM manipulation (document.createElement + ReactDOM.createRoot for each button). The cleanest approach for RSC compatibility: wrap renderedContent in a div with ref, useEffect queries pre elements, for each pre: wrap it in a relative div and append a CopyButton container. Use ReactDOM.createRoot to render CopyButton into each container. Import createRoot from react-dom/client.

    4. **markdown-renderer.tsx** -- Add prose-pre:overflow-x-auto to the article className for D-11 mobile horizontal scrolling on code blocks. This ensures pre elements inside the prose container get overflow-x: auto.

| T-05-04 | Information Disclosure | copy-button.tsx clipboard write | accept | Clipboard API requires user activation (click); browser enforces secure context (HTTPS); copies only visible code text |
| T-05-05 | Tampering | paste-view.tsx DOM manipulation | accept | Modifies only the current user's view (adds copy buttons to pre elements); no data sent to server; cosmetic DOM changes only |
